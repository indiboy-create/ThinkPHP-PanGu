关于 PanGu

PanGu 不是框架，而是一张索引：把散落在 GitHub 上的组件、模板、服务与发布包，按“能装、能跑、能看懂”整理到一起。

Structure

仓库如何组织

按交付形态分成六类：Composer 组件、前端模板、独立服务、商店发布包、文档界面与探索项目。

think-* Composer 组件

51 个以 youvision/think-* 发布的 Composer 包，覆盖从插件骨架到认证、支付、短信与后台组件的常见需求。

LayuiAdmin-Iframe

原生 HTML + CSS + JavaScript 的 iframe 后台模板，沿用 Layui AMD 模块体系，并带 Vite 开发服务器与静态构建脚本。

glide-server

URL 参数驱动的按需缩略图服务，首次访问时生成并缓存，可脱离 ThinkPHP 独立部署。

应用商店套件

think-store 负责发布包查询、同步与静态资源部署；示例、编辑器、象棋与天气是可安装的发布包。

think-apidoc-ui

Layui 版 ApiDoc 前端界面，纯静态资源，放入 public/apidoc 并改一处 config.js 即可使用。

探索项目

tpcms-sites 是仍在演进的站群系统；xiaozhi-music 是面向小智 AI 的 Meting 音乐 MCP 服务。

Conventions

本站的整理原则

可验证、可操作、不过度包装：页面上的每个结论都能回到源仓库。

以 README 为准

说明与接口优先取自 README 与 composer.json；只有名称、没有实质说明的仓库不收录。

区分组件与工程

Composer 包、前端模板、独立服务与发布包分开呈现，不把不同交付形态混在同一套安装说明里。

纯静态交付

页面为静态 HTML，数据集中在 data.js，可托管到 GitHub Pages、对象存储或任意静态服务器。

指向源仓库

每个组件与项目都提供 GitHub 链接，版本、更新记录与问题讨论以源仓库为准。

环境基线

组件基线为 PHP 8+ 与 ThinkPHP 8；glide-server 要求 PHP 8.3+，并由 nginx 或 Apache 转发请求。

安全提示

模板编辑、数据库备份、支付与后台接口类组件，生产环境应配置鉴权中间件、路径白名单与频率限制。

Tech

本站技术栈

Vite 只负责开发服务器与热更新，生产构建由 Node 脚本输出静态文件；线上不依赖任何服务端运行时。

Layui 2.13.9

导航、分页、弹层与基础样式，静态资源位于 src/component/layui，构建时原样保留。

原生 JavaScript

数据渲染、搜索筛选、URL 同步与复制命令均由一个通用脚本处理。

集中数据源

组件与项目数据维护在 data.js，页面按需读取并渲染，避免重复维护。

静态托管

把 dist 目录作为站点根即可部署，不需要 PHP、数据库或 Node 运行环境。

数据与源码

本站源码与每个项目都在 GitHub。发现描述不准确，欢迎直接提 Issue 或 Pull Request。
